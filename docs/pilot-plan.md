# في طريقي — خطة الـ Pilot وقائمة الإطلاق

**الحالة:** مسودة تشغيلية. البنود القانونية والتنظيمية تحتاج مراجعة بشرية مختصة قبل الإطلاق ولا تُعد معتمدة.

## النطاق
- منطقة جغرافية واحدة، وقائمة مناطق وقواعد توافق حقيقية (بدل بيانات `seed_areas` التجريبية).
- 10–20 سائقًا موثّقًا يدويًا و30–50 عميلًا مدعوًّا. الحسابات الداخلية تُوسم `is_test_account`.
- مدة مقترحة: 4 أسابيع، مراجعة المؤشرات أسبوعيًا (docs/kpis.md).

## تهيئة السائقين (cold start)
1. تجنيد مسبق قبل فتح التسجيل للعملاء.
2. التحقق من الرخصة والمركبة خارج التطبيق، ثم «توثيق السائق» من لوحة الإدارة.
3. شرح وضع السائق: الموقع أثناء فتح التطبيق فقط، والوجهة المؤقتة، وعدم استخدام التطبيق أثناء القيادة.

## قائمة الإطلاق
| البند | الحالة |
|---|---|
| قبول AC 1–14 | مغطى آليًا في `backend/tests/test_acceptance.py`؛ الجزء المتزامن من AC 8 يُشغَّل على PostgreSQL |
| توثيق السائق قبل الاستقبال | منفّذ (`DRIVER_VERIFICATION_REQUIRED`) |
| إخفاء الهاتف إلا للطرفين المرتبطين | منفّذ ومختبر (`tests/test_security.py`) |
| البلاغات ومراجعتها وإيقاف الحسابات | منفّذ |
| سجل تغييرات الحالات | منفّذ |
| إرشادات السلامة / الشروط / الخصوصية | صفحات موجودة؛ الشروط والخصوصية مسودة تحتاج مراجعة قانونية |
| مراجعة قانونية/تنظيمية محلية (النقل، التراخيص، الخصوصية) | **غير منجزة، مسؤولية صاحب المنتج** |
| مفاتيح VAPID وخدمة SMS حقيقية | تُضبط في بيئة الإنتاج (الإقلاع يفشل إن كانت SMS من نوع console) |
| مراقبة الأخطاء (Sentry)، نسخ احتياطي، تنبيه توقف | **غير منجزة** (OPS مؤجلة مع CI/CD) |
| اختبار حمل خفيف | **غير منجز** |
| Playwright E2E على المتصفح | **غير منجز**؛ التغطية الحالية عبر API واختبارات الواجهة بـ Vitest |

## معايير نجاح الـ Pilot (مقترحة، تُعتمد من صاحب المنتج)
- معدل تأكيد ≥ 30% من الطلبات المحسومة، وزمن أول اهتمام < 10 دقائق في ساعات الذروة.
- لا حادثة سلامة غير معالجة؛ كل البلاغات تُراجع خلال 24 ساعة.
